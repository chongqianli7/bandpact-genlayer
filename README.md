# BandPact

[Canonical contract](https://explorer-studio.genlayer.com/address/0xb07d57b5F8275722605C7a97D4A979d32Ce8d2E7) · [Evidence](evidence/studionet.json) · [Validation](VALIDATION.md)

A reusable GenLayer Intelligent Contract for reconciling two separately signed integer interval reports. Independent semantic consensus determines whether both reports describe the same quantity. Deterministic code computes their common band. Both parties must then approve the exact same result digest before the record becomes AGREED.

No frontend, backend, paid model API, oracle operator or fund custody is required.

## Example

Two archive systems report newly accessioned objects in the same collection and UTC month, using distinct-object-ID counting. Their descriptions use different wording. One signs `[90,110]`, the other `[100,120]`. If validators agree on all four definition facets, code produces `[100,110]`. One party's approval leaves AWAITING_APPROVAL; only the second distinct party can complete agreement.

An overlap alone is insufficient. Counting upload events and counting unique objects are different bases even if both intervals contain 100. A missing time zone requires review rather than an assumed match. No common integer produces DISJOINT even when definitions match.

These are declared admissible count bands, not confidence intervals. Their intersection does not establish statistical confidence, accuracy or real-world truth.

## Consensus and state

The two participants sign their own immutable report with four text facets: metric, population, window and basis. The leader and validators independently classify every facet as SAME, DIFFERENT or UNCLEAR. All four decision labels must agree. Complete original facet texts are inserted into findings by code, avoiding generated quotation errors. Explanation wording need not match and does not alter arithmetic or permissions.

The model receives no numeric bounds or approval state. Its semantic judgment cannot be influenced by whether numbers appear to overlap. Model output cannot choose, expand or shrink an interval. After consensus, code computes `max(lower)` and `min(upper)` with exact integer arithmetic.

State: COLLECTING → READY → AWAITING_APPROVAL → AGREED. Alternative terminal assessment states are INCOMPARABLE, REVIEW and DISJOINT. A DIFFERENT facet dominates UNCLEAR. Each party has one immutable report and one approval. There is no owner override, edit, replacement or Appeal.

## Use

Deploy `contracts/band_pact.py` with no constructor arguments on **Stable Studionet, chain 61999**.

1. Owner calls `open_pact(id, peer, unit)` with a distinct nonzero peer wallet and an opaque shared unit code such as `OBJECT`.
2. Each participant calls `submit_report(owner, id, payload)` from its own wallet. Examples are `examples/report-a.json` and `examples/report-b.json`. The submitted numeric band is in whole units of the declared scale; no conversion occurs.
3. Either participant calls `compare(owner, id)` after both reports exist. Wait for successful finalized full consensus.
4. Read `get_pact(owner, id)`. Inspect original reports, four findings, computed intersection and result digest.
5. Each participant calls `approve(owner, id, result_digest)`. Either may approve first. They must both sign the same exact digest. AGREED is immutable.

| Method | Kind | Arguments |
|---|---|---|
| open_pact | write | pact_id, peer, unit |
| submit_report | write | owner, pact_id, payload |
| compare | write | owner, pact_id |
| approve | write | owner, pact_id, result_digest |
| get_pact | view | owner, pact_id |
| get_protocol | view | none; returns `bandpact-1` |

Every argument is a string; report bounds are JSON integers inside the payload. View methods return strings. IDs are scoped to the opening wallet. See [PROTOCOL.md](PROTOCOL.md) for exact bounds, digest construction and integration rules.

Other checks cover numeric prompt withholding, evidence binding, ownership, per-party reports, replay, digests, incomplete input and independent disagreement. SDK tests use real pinned storage/calldata with mocked LLM responses. These tests do not establish live consensus. `schema.json` is generated by the official linter.

[Network evidence](evidence/studionet.json) contains actual transactions, state checkpoints and final record. [VALIDATION.md](VALIDATION.md) separates those observations from local coverage. `read-live.mjs` makes no writes and needs no signing key; it rechecks deployed source, receipts, exact calldata, arithmetic, digest and final state.

`verify-live.mjs` is an opt-in development write harness. Set `BANDPACT_NEW=1` once to create dedicated zero-value test accounts. Their keys stay in a private local state file outside the repository. The harness saves intent before sending, persists returned hashes before polling and resumes existing hashes. An unknown submission remains locked. Inspect a failure before making any new explicit attempt; no automatic resend or Appeal is provided. Do not run this harness merely to read the published example.

## Limits

- The contract reconciles signed assertions, not measurements. It does not authenticate a data source, inspect archive records, verify identities, establish independence or prove either numerical interval is true. A single person may control both wallets. Reports become visible immediately; there is no commit-reveal or anti-copying guarantee.
- Consensus compares descriptions only. SAME means the supplied definitions appear equivalent under this fixed policy, not that a report is complete or accurate. Missing details, correlated model mistakes and prompt injection remain possible. URLs in text are not fetched.
- Only nonnegative closed integer bands up to 10^12 are supported. No decimals, negative values, unit conversion, rounding, averaging, probability model, weighted trust, negotiated midpoint or selection of one exact count.
- The unit code is an opaque shared label, not a validated physical unit. Each report must explicitly describe its quantity and scale. Ambiguous scales or conflicting definitions should yield REVIEW/INCOMPARABLE, but semantic detection can fail.
- AGREED is an application acknowledgement of the exact overlap and reports. It is not a legal agreement, payment instruction, proof of data quality or certification. Either participant can stall by withholding a report or approval.
- No expiry, revocation, amendments, third reporter, live refresh or cross-deployment identity. Corrections require a new pact ID. Total pacts per deployment are unbounded; each pact stores exactly two bounded reports.
- All submitted definitions, bounds, findings and approvals are public. Use public or synthetic metadata and avoid personal, confidential or credential data.
